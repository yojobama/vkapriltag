# Progress: own types (Phase 4b stage S2, branch research/2026-11-own-types, base bbb9d0d)

Goal of S2: replace the upstream types at the library's boundaries (`apriltag_family_t`, `struct quad`, `image_u8_t`,
`apriltag_detection_t`, `zarray_t`, `matd_t`, `apriltag_detector_t`) with the library's own, without changing any
output. No public or internal library header includes upstream afterwards (`deps_lint` ctest). Desktop only.

## Sub-steps (one commit each; every commit builds and passes ctest)
1. `Types.h` (Image, Quad), `Family.h`, `Detection.h`; the family tables generated by `tools/gen_families.py` from the
   fetched upstream sources (8 families, 3.8 MB of generated data); ctest `families_match_upstream` compares every
   table, code word and cell with the tables upstream builds.
2. Patched-upstream decode path removed (`APRILTAG_VK_OWN_DECODE=0`, its registry entry, `quad_decode_index`,
   `quad_sample_code`, `apriltag_min_hamming`, `reconcile_detections`, `TakeHomography`). An unsupported family makes
   `Decode()` throw `std::invalid_argument` instead of falling back.
3. `Image`/`Quad` in RefineEdges, BorderSample, PolishFit, OwnDecode, TagDecoder and the test hooks. `RefineEdges` takes
   the decimation and the border width in cells instead of the detector. `FitSmallQuad` takes a row stride.
4. `Family`/`Detection`/`DetectionList`/`TagDecoderConfig` at every boundary (TagDecoder, TrackingDetector,
   FramePipeline, PoseEstimator, PolishFit, OwnDecode), the apps, tools and tests; `deps_lint`;
   `VKAPRILTAG_UPSTREAM_VALIDATION`; the vkapriltag target no longer links apriltag.
5. A strided-image unit test (`unit_steps`), the log.

## Design notes
- `Family` is a value with pointers to static tables plus an explicit `max_hamming` (default 2, 0 to 3), so a copy with
  another limit is cheap; the decoder compares pointer and `max_hamming` to decide whether to rebuild its tables.
  `MaxCorrectedBits` (the ApplyFamilyLimits heuristic) is unchanged and independent of `max_hamming`.
- `Detection` keeps upstream's field names (`id`, `hamming`, `decision_margin`, `c`, `p`, `H`) and corner order; `H` is
  `double[9]` row-major, exactly what the matd held. `DetectionList` is a `std::vector<Detection>`.
- `TagDecoder::Decode()` returns `const DetectionList &`, valid until the next `Decode()` (the old contract). The
  per-quad scratch is a `std::vector<DetectionList>` that is cleared, not freed, between frames; the merge copies.
- `OwnDecode::SortById` sorts an array of pointers with `qsort` and the same comparator and then permutes, because the
  order of equal ids depends on the sort algorithm and the element size (upstream sorted an array of pointers);
  `Reconcile` removes with the same "move the last one into the hole" rule as `zarray_remove_index(..., shuffle=1)`.
- `TrackingDetector::Detect()` returns `const DetectionList &`; the tracked path builds the list of accepted tags in its
  own member (the decoder's list is no longer edited in place), the full path returns the decoder's list.
- `Image` carries the stride everywhere the library samples (OwnDecode, ReadBorder, the geometry templates, PolishFit,
  FitSmallQuad). `TagDecoder::Decode(quads, Image, reversed_border)` takes a strided frame; the pointer overload stays
  for tightly packed frames. The tracking crops and the GPU upload still assume tight rows (not touched).
- Upstream stays only in: `tests/own_decode_test.cpp`, `tools/upstream/UpstreamAdapter.h`, `tools/vk_eval/vk_eval_ref.cpp`
  (`vk_eval --ref`), `tools/validate_against_libapriltag/*`, `tools/validate_pose*/`, `tools/synth_pose_ground_truth/`.
  `VKAPRILTAG_UPSTREAM_VALIDATION=OFF` does not fetch upstream: library, vk_eval, track_eval, bench_multiqueue, the unit
  tests, golden, options_lint and deps_lint build and pass without it (build dir `build-own-types-off`).

## Gate results (desktop, RX 9060 XT; base = build of bbb9d0d in `build-own-types-base`)
- ctest, 16 of 16 (own_decode_random / reconcile / corpus / comparison_can_fail, families_match_upstream, 8 unit groups,
  golden_detections, options_lint, deps_lint); 11 of 11 with `VKAPRILTAG_UPSTREAM_VALIDATION=OFF`.
- Golden detections also pass with each of the four `APRILTAG_VK_FORCE_NO_*` flags and with all four set.
- Corpus, 26 scenarios, d1 and d2, six switch sets (default, `SMALL_RESCUE=1 HULL_QUAD=1`, `POLISH=1`, `GREY_MARGIN=0`,
  `THIRD_BIT=0`, `FAMILY_LIMITS=0`), base twice and new once per set (`variants.sh`, `cmpdump.py`; family16h5 included):
  no frame differs in ids or Hamming distance in any run. At d2, new differs from base in at most one frame of one
  scenario (noise, 0.0003 to 0.0027 px; large-tags 0.0004 px under limits0), and base differs from itself the same way
  (third0). At d1 base differs from itself in 1 to 5 frames and new from base in 1 to 7, all corner shifts at most
  0.0022 px. The GPU front end is not deterministic (see the own-decode log); to settle it, 16 runs each of noise d2:
  base 13 x dump A + 3 x dump B, new 13 x A + 3 x B; family16h5 d1: base 13 + 3, new 14 + 2 (the same two dumps).
- track_eval, ten sequences, `full` and `key` modes, base twice and new twice: 0 differing detection lines between any
  pair (tracked path exercised: 175 tracked frames in slow-3tag-640 key mode). `async` and `asyncsync` modes run.
  bench_multiqueue (depth 2, 100 frames): 0 mismatches.
- `apriltag_pose_validate --data` on many-tags frame 0 (d2): output identical to base except the wall-clock numbers and
  the pipeline-cache messages.
- Timing, `vk_eval --iterations 8 --warmup 5`, interleaved ABBA, 4 rounds (16 runs per row), d2, from `timing.py`
  (cpu = QuadDecode + TagDecoder, ms per frame, base/new, above 1 means new is faster):

  | scenario | new cpu | base cpu | ratio |
  | --- | --- | --- | --- |
  | one-tag | 0.0628 | 0.0631 | x1.006 |
  | many-tags | 0.1373 | 0.1364 | x0.994 |
  | dense-tags | 0.2812 | 0.2863 | x1.018 |
  | clutter-only | 0.1659 | 0.1739 | x1.048 |
  | jpeg | 0.3698 | 0.3758 | x1.016 |

  Repeat with 6 rounds for many-tags and one-tag at d1 and d2: x1.010, x0.998, x0.988, x1.011. No slowdown beyond noise.
